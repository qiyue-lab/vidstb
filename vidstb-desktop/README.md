# Vidstb 电脑版

把 Android 项目 `vidstb-master` 里的「提取视频内嵌字幕 → 生成硬字幕」功能移植到电脑端。
界面是本地网页，后端只依赖 Python 标准库，ffmpeg 调用本机的完整版（含 libass）。
此外还提供了一个独立的「视频合并」功能：多段视频首尾相接，统一输出 3840×2160 / 60fps。

手机端受硬件限制转码很慢，电脑版在此基础上补了三件事：

- **显卡硬件加速**：自动检测 NVIDIA NVENC / Intel QSV / AMD AMF，失败自动回退 CPU。
- **批量队列**：一次导入多个视频排队处理，可并行多个任务。
- **视频合并**：多段合并并统一升到 4K60，合并前给出体积预估，还能抽样实测校准。

## 快速开始

```bash
# 双击 启动.bat，或命令行运行
python server.py
```

启动后会自动打开浏览器 `http://127.0.0.1:8777`（端口被占用时自动往后找）。
Ctrl+C 退出。

## 使用流程

1. 点「选择视频」（优先调用系统文件选择框，失败会回退到内置文件浏览器），
   也可以直接粘贴绝对路径，或用「扫描文件夹」一次性导入整个目录。
2. 每个视频会列出内嵌字幕轨：语言 · 标题 · 格式 · 默认 / 强制标记，
   默认勾选默认轨；SRT / ASS / SSA / mov_text / WebVTT 可选，
   PGS、VobSub 等图片字幕标记为「暂不支持」（需要 OCR）。
3. 在「输出设置」里选择编码模式、输出目录、容器、并行数，展开「字幕样式」可覆盖字体。
4. 点「加入队列」，任务自动开始，进度、倍速、剩余时间实时刷新，可单独取消 / 重试 / 删除。
5. 完成后点「打开位置」直接在资源管理器里定位结果。

## 视频合并（4K60）

在顶部切到「视频合并（4K60）」标签页：

1. 点「选择视频」或「扫描文件夹」导入片段，列表顺序就是合并顺序，
   可用 ↑ / ↓ 调整。
2. 输出规格**固定为 3840×2160 / 60fps**，可改的是：目标码率、音轨码率、
   容器（默认 MP4）、画面适配方式、CPU 编码预设。
3. 选好两段以上后，「合并预估」会立刻给出预计文件大小、总时长和片段数。
4. 点「开始合并」加入队列，进度与硬字幕任务共用同一个队列。

### 画面适配

不同比例的素材统一到 16:9 有三种做法：

| 模式 | 效果 | 说明 |
| --- | --- | --- |
| `pad`（默认） | 保持比例 + 左右或上下黑边 | 不变形，画面完整 |
| `crop` | 放大后裁掉超出部分 | 不变形，边缘内容会丢失 |
| `stretch` | 直接拉满 | 画面会变形 |

### 关于体积预估

合并界面显示的大小有两个口径：

- **上限估算（默认，即时）**：`目标码率 × 总时长`。CQ / VBR 编码器会按画面复杂度
  自适应省码率，画面简单的片段实际会明显小于这个值，所以它只是上限。
- **实测校准（点按钮）**：对每段抽中间 2 秒做一次真实编码，测出每段实际码率，
  再按各自时长加权外推。实测偏差通常在 5% 以内（测试素材上为 1.5%）。

音轨统一重编码为 AAC 立体声 48kHz；没有音轨的片段会自动补等长静音，
保证 concat 时各段参数一致、不会音画错位。

## 网盘资源库

把找到的夸克 / 百度网盘分享链接存下来，并在本页直接查看里面的文件，
不用每次都复制链接去浏览器确认里面有什么。

- **添加**：整段分享文案直接粘进输入框就行（含「提取码：xxxx」也能自动识别），
  标题留空会先自动填一个，之后随时可以改。
- **改标题 / 补标题**：
  - 直接点卡片上的标题（或旁边的 ✏️）就地改，回车保存、Esc 取消；
  - 点「编辑」打开弹窗，一次改标题、标签、备注、提取码、链接；
  - 读取过文件清单后，卡片会给出「建议标题」（按顶层目录名 / 文件名公共前缀猜的，
    自动去掉 1080p、WEB-DL、x264 这类尾巴），点一下就采用。
  - 手工填过标签就不会被改标题覆盖；只有程序自动猜的标签会跟着新标题更新。
  - 标题清空会自动回退，不会留下一条没名字的记录。
- **查看文件（夸克）**：点「读取文件」，后台递归读取分享目录树，
  在弹窗里按层级展示，视频文件加粗高亮、显示大小，可按文件名过滤，
  一键复制整个文件清单。**不需要登录 Cookie。**
- **查看文件（百度）**：点「读取文件」，自动带上提取码打开分享页并读出顶层内容，
  同样在弹窗里展示、可复制清单。**也不需要登录 Cookie**，但有以下限制：
  - 百度未登录时只开放**顶层**内容，子目录列不出来（接口一律返回 errno 2），
    弹窗会提示「N 个文件夹未展开」，点「在浏览器打开」看完整内容；
  - 如果分享顶层直接就是视频文件（很常见），那看到的就是完整清单；
  - 想展开子目录：把浏览器里百度网盘的 Cookie 填到 `config.json` 的
    `baidu_cookie`（只存本机，不上传），程序才会尝试递归。
    这条路径百度随时可能改，失败会自动回退成顶层。
- **管理**：搜索（标题 / 标签 / 链接 / 文件名都能搜）、按网盘和状态筛选、
  标签快速切换、想看 / 在看 / 已看 / 已失效四种状态、导出导入 JSON 备份。
- **分组**：自己建分组（如「国漫」「待搬运」），一条资源只属于一个分组。
  - 顶部分组栏显示每组的**条数和总大小**，点一下就只看这一组；
    「未分组」也是一个入口，选中某个分组后可改名 / 删除
  - 删除分组**不会删资源**，组里的资源回到「未分组」
  - 单条：卡片上的「移动到」下拉直接改；批量：勾选多条后顶部「移动」按钮
  - 分组和标签是两个维度，可以同时用（比如「国漫」组 + 「4K」标签）
- **回收站**：删除不会直接消失，先进回收站（按钮上带数量），可随时「恢复」；
  回收站里再删一次才彻底消失，也有「清空回收站」。
- 数据存在 `runtime/resources.json`，整个目录拷走即用，不会写到系统盘。
  每次保存都会同步一份 `resources.json.bak`（最新版）和 `.bak2`（上一版）；
  万一主文件被误删或损坏，下次启动会自动从备份恢复，并在页面顶部提示恢复了几条。

> 解析用的是夸克分享页自己的公开只读接口，程序不会登录、不会转存、
> 也不会上传任何数据；只读取文件名、大小、层级。

## 参数说明（与手机版的对应关系）

| 项目 | Android 版 | 电脑版 |
| --- | --- | --- |
| 软件编码 | libx264 + CRF 16 + slow | 相同，CRF 与 preset 可改 |
| 硬件编码 | h264_mediacodec | h264_nvenc / h264_qsv / h264_amf，按源码率 × 倍率给目标码率 |
| 失败回退 | 硬件失败回退软件 | 相同（编码模式选「自动」时） |
| 分辨率 / 帧率 | 保持源规格，不缩放 | 相同 |
| 音频 | `-c:a copy` 直接复制 | 相同；输出 MP4 且音轨装不下时自动转 AAC 320k |
| 多字幕布局 | 底部向上错位，`MarginV = max(24, h/18) + i × max(36, h/12)` | 完全相同 |
| 字体 | fontconfig 指向 /system/fonts | 自动生成 fonts.conf，指向系统字体目录 + MKV 内嵌字体附件 |
| 输出 | Movies/Vidstb 下的 MKV | 与源视频同目录（可改），MKV / MP4 可选 |

```text
vidstb-desktop/
├── server.py              本地 Web 服务（仅标准库）与 REST / SSE 接口
├── install_ffmpeg.py      下载完整版 ffmpeg 并写入 PATH
├── 启动.bat               Windows 双击启动
├── config.json            运行后生成，保存输出目录、编码偏好等设置
├── app/
│   ├── models.py          VideoMetadata / SubtitleTrack / ProbeResult
│   ├── config.py          配置读写
│   ├── ffmpeg_tool.py     定位并调用 ffmpeg / ffprobe
│   ├── media_probe.py     ffprobe 解析（对应 MediaProbe.java）
│   ├── command_builder.py ffmpeg 命令与字幕滤镜（对应 FFmpegCommandBuilder.java）
│   ├── hardware.py        显卡编码器检测与冒烟测试
│   ├── fonts.py           fontconfig 配置（对应 SubtitleFonts.java）
│   ├── runner.py          ffmpeg 子进程与进度解析
│   ├── merger.py          多段合并为 4K60：滤镜图、命令、体积预估、抽样实测
│   ├── jobs.py            批量队列（含合并任务）、取消、重试、硬件失败回退
│   ├── quark.py           夸克网盘分享链接解析（公开只读接口，免登录）
│   ├── resources.py       网盘资源库存储、搜索、标签、状态
│   ├── quark.py           夸克分享解析（免登录，可递归子目录）
│   ├── baidu.py           百度分享解析（免登录，默认只读顶层）
│   └── fs_browse.py       文件系统浏览、目录扫描、系统文件选择框
├── web/                   index.html / styles.css / app.js
├── runtime/resources.json 网盘资源库数据（运行后生成）
└── tests/                 单元测试
```

## 环境要求

- Python 3.9 及以上（只用标准库，无需 pip 安装任何东西）。
- ffmpeg / ffprobe **完整版**（必须带 libass，否则没有 `subtitles` 滤镜）。
  当前机器已安装在 `D:\tools\ffmpeg\bin`，并已写入用户级 PATH。
  换机器或重装可执行：

  ```bash
  python install_ffmpeg.py              # 默认装到 D:\tools\ffmpeg 并写入 PATH
  python install_ffmpeg.py --dest E:\ffmpeg
  ```

## 测试

```bash
python -m unittest discover -s tests
```

覆盖字幕滤镜与路径转义、多字幕错位间距、码率计算、显卡编码参数、
MP4 音轨转码、ffprobe 解析（对应 Android 版 FFmpegCommandBuilderTest / MediaProbeTest），
以及合并模块的滤镜图构造、命令参数、体积预估与抽样实测加权。

## 已知限制

- 不支持 PGS、VobSub 等图片字幕，也不做 OCR。
- 合并输出的 4K 是把低分辨率素材放大得到的，**不会让画面变得更清晰**。
- 合并始终重编码（因为要统一分辨率与帧率），不支持直接流拷贝拼接。
- 复杂 ASS 的绝对定位与特效可能需要额外适配；多字幕使用固定间距错位布局。
- HDR、特殊色彩空间尚未验证。
- 文件名含单引号 / 双引号时，ffmpeg 滤镜表达式无法转义，会自动改为「先导出字幕流再烧录」，
  结果一致但多一步临时文件。
- 转码会改变像素，无法做到数学意义上的无损，只能尽量保留视觉质量。
